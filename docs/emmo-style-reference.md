## 1. 调研方法

早期尝试直接抓取 emmo.club 均失败。最终跑通的完整链路：

| 步骤 | 手段 | 产出 |
| --- | --- | --- |
| 1. 页面截图 | Edge 无头模式截图 | 页面视觉 |
| 2. DOM 导出 | `--dump-dom` | 页面结构与资源清单 |
| 3. 样式表下载 | `curl` 取 Astro 构建产物的 CSS | **精确色值与圆角** |
| 4. 素材下载 | `curl` 取 `/assets/doodles/` 下的资源 | **角色的 SVG 源码** |

**关键前提**：域名必须带 `www.` 前缀。`emmo.club` 无法解析，`www.emmo.club` 正常。这一点决定了前几次尝试全部失败。

**环境依赖**：本机 v2rayN 提供 10808（SOCKS）与 10809（HTTP）代理，Windows 系统代理开关为关闭状态，但流量转发生效，`www.emmo.club` 可直连。

**未取到的部分**：App Store 页面与国内应用商店均不可达，因此**产品实际界面（App 内 UI）尚未获得**。本文档的结论覆盖品牌站与角色素材，不含 App 交互界面。

## 3. 角色绘制手法

素材位于 `/assets/doodles/`，共 49 个文件。其中仅 `smile.svg`、`line.svg`、`link.svg` 为矢量，其余为 PNG。

对 `smile.svg`（300×300，18.9 KB）的源码分析：

### 3.1 构造方式

| 部件 | 实现 | 关键属性 |
| --- | --- | --- |
| 主体 | **单条手绘不规则 blob 路径** | `fill="#FED55D"` |
| 描边 | 同一条路径的 stroke | `stroke="#7F6B2F"`，`stroke-width="2"` |
| 眼睛 | 两个**不对称**的黑色实心形状 | `fill="black"` |
| 眼神光 | 数个主体色小路径叠在眼睛上 | `fill="#FED55D"` |
| 嘴巴 | 粗弧线描边，左端起笔处有钩状收笔 | `stroke="#7F6B2F"` |

### 3.2 三条可复用的技法

**技法一：描边用同色系深色，不用黑。**
`#7F6B2F` 是主体色 `#FED55D` 的同色相深色。角色整体保持一个色相家族，
避免黑色描边带来的生硬对比。

**技法二：表情必须不对称。**
两只眼睛一只为小点、一只为倾斜豆形。完全对称会让角色呆板。
嘴巴弧线两端粗细不一，左端有明显收笔。

**技法三：高光点制造生气。**
在黑色眼睛上叠加主体色的小点，形成眼神光。这是「可爱」感的重要来源。

### 3.3 两种描边处理并存

| 场景 | 描边 | 依据 |
| --- | --- | --- |
| 网站装饰角色 | 同色系深色 `#7F6B2F`，宽 2 | `smile.svg` |
| App 图标 | **粗黑描边** | `emmoLedger.png` |

二者都是手绘不规则 blob，但描边处理不同。App 图标在深色背景与小组件
中需要更强的辨识度，故用黑；网站装饰角色追求柔和，故用同色系深色。

## 4. 品牌与设计哲学

从站点「关于我们」提取，这是比色值更根本的东西：

> 我们想做很多美好的 App，是因为生活本来就已经有很多匆忙和压力了。
> 有时候，人只是想记录一下今天的体重，喝了几杯水，走了多少步；
> 有时候，也只是想用一个小贴纸表达"今天有点累，但我还在好好生活"。
>
> 所以我们希望 **App 不只是工具，而是一个温柔的陪伴**。
> 它可以提醒你吃得更健康，也可以**接住你偶尔的松懈**；
> 它可以帮你规划目标，也**不会催促你必须完美**。
>
> 让每一个认真生活的人，都能在打开 App 的时候，
> 感觉自己**被轻轻支持了一下**。

品牌主张：**「用心创造小美好」**

三条可直接指导设计的推论：

| 推论 | 说明 |
| --- | --- |
| 不做「效率工具」 | 不出现催促性文案、不制造完成焦虑、不用红色警示施压 |
| 允许不完美 | 空状态、失败态都应温和，而非报错式语气 |
| 情绪价值优先于信息密度 | 宁可留白，也不把界面塞满 |

### 4.1 产品线

| 产品 | 定位 |
| --- | --- |
| emmo 日记 | 治愈风日记 |
| emmo 小账本 | 记账与存金 |
| Prodrafts | 无限草稿，自然手写 |
| 微笑 todo | 自律计划与时间打卡 |
| Golite | 体重管理 |
| SleepCore | 睡眠改善 |
| logus | 2 秒 vlog |

七款产品的共同点：都是「轻量、日常、情绪向」的个人记录工具。

## 5. 与现有设计系统的差异

`03-design-system.md` 的方案建立在文字描述推测之上，实测后需修正五处：

| 项目 | 现有方案（推测） | 实测 | 处置建议 |
| --- | --- | --- | --- |
| 文字色 | `--ink-1: #3B342C` 暖黑 | `#3B3B3F` / `#151515`，**中性** | **需改**。EMMO 是暖底配中性字，暖底配暖字会发闷 |
| 主色 | `--macaron-mint: #8DC3A7` 薄荷绿 | `#FFD84F` 暖黄 | 需确认。也可保留多色板，把暖黄加入 |
| 页面底色 | `--paper-1: #FAF5EC` | `#FFFDF6` | 需改。现有的偏黄偏深 |
| 大圆角 | 最大 `28px` | `46px` / `56px` | 建议扩充刻度 |
| 阴影色 | `rgba(59, 52, 44, …)` 暖调 | `rgba(40, 40, 45, …)` 中性 | 建议改中性 |
| 描边色 | 未定义 | `#7F6B2F` 式同色系深色 | **新增**。这是角色绘制的关键技法 |

**保留正确的部分**：卡片圆角 `28px` 与实测完全一致；`blur(12px)` 毛玻璃一致；
`prefers-reduced-motion` 的处理一致。

## 8. App 界面实测（2026-09-18 补充）

素材来源：用户提供的 5 张手机截图，覆盖 logus（vlog 应用）的首页、偏好设置、设置页，
以及 emmo corp 的产品总览页。

### 8.1 关键更正：底色不是暖奶油

此前从网站提取到 `#FFFDF6` 并据此把页面底色定为暖奶油，**这是错的**。该色是网站
某个局部元素的色值，不是页面底色。

实际情况：

| 层 | 色 | 说明 |
| --- | --- | --- |
| 页面底色 | 近白，略带冷灰 | 不是纯白，但绝不是奶油黄 |
| 卡片 | 纯白 `#FFFFFF` | 与底色形成轻微层次 |
| 分隔线 | 极浅灰 | 仅产品总览页有 |

**结论**：这是标准的「白卡片 + 近白底」层级，靠极小的明度差区分，而非靠颜色。
此前方案里的暖奶油底（`#FAF5EC`）偏黄过重，已修正为 `#FBFBFA`。

### 8.2 色彩系统：11 套主题

logus 的偏好设置页展示了完整的配色方案，共 **11 个色板**：

**纯色 7 套**：玫红、淡黄、薄荷、翠绿、天蓝、宝蓝、淡紫
**渐变 4 套**：蓝紫、粉紫蓝、淡紫、橙粉

**此前遗漏的维度：渐变也是色板的一部分。** 本项目的方案只有纯色。

选中态的表现：**黑色圆环**（约 2px），环与色块之间留有一圈空隙。
注意不是主题色环——用黑色保证在任何色板上都清晰可辨。

### 8.3 形状与层级

| 元素 | 处理 |
| --- | --- |
| 卡片圆角 | 约 20 至 28px |
| 胶囊 | 全圆角 |
| 图标按钮 | 圆形，白底，柔和阴影，悬浮于底色之上 |
| 底部导航 | 悬浮白色圆角条，非贴边 |
| 分段控件 | 选中项为浮动的白色胶囊，带阴影 |

**共性**：大量使用「白色 + 大圆角 + 柔和阴影」的悬浮元素，压在略暗的底色上。
这是 iOS 风格语言，与网站的手绘扁平风格并不相同。

### 8.4 布局范式

**设置列表**（可直接复用）：

```
分组标题（灰字，在卡片外）
┌─────────────────────┐
│ 标签          >      │   ← 白卡片，大圆角
│ 标签          >      │   ← 行间不用分隔线，靠间距
│ 标签          >      │
└─────────────────────┘
辅助说明（灰字，在卡片外）
```

**要点**：分组标题与辅助说明都在卡片外；行内是「左标签 + 右箭头」；
箭头是灰色而非主题色。

**内容网格**：两列，卡片内是媒体内容，文字叠在图上并加轻微阴影。

### 8.5 角色体系（本项目缺失的部分）

五张截图里，角色出现在：

| 场景 | 处理 |
| --- | --- |
| 产品图标 | 每款产品一个专属 blob，形状各异（圆形、花瓣形、锥形） |
| 装饰条 | 首页顶部一排 10 个同色小角色 |
| 空状态 | 「+vlog 还没记录，去拍一个吧」配一个角色 |
| 导航中央按钮 | 角色脸作为主操作入口 |

**这是 EMMO 品牌识别度的核心载体，而本项目完全没有对应物。**

现有的图标体系是几何描边风格（`stroke-width: 1.75`、24×24 栅格），
与角色体系的手绘实心 blob（粗黑描边、不规则轮廓、300×300 画布）是
两套完全不同的视觉语言。

二者的分工应当是：

| 层级 | 用途 | 风格 |
| --- | --- | --- |
| 几何图标 | 界面功能：导航、按钮、状态 | 现有体系，保持 |
| 角色 blob | 品牌表达：工具图标、空状态、装饰 | 需新建 |

### 8.6 文案语气

空状态写的是「还没记录，去拍一个吧 / 点我，拍摄」，是邀请而非提示。

这与官网的品牌陈述一致——「不会催促你必须完美」「接住你偶尔的松懈」。
界面文案应遵循同一语气：不催促、不评判、不用感叹号施压。

### 8.7 与网站的差异

| 维度 | 网站 | App |
| --- | --- | --- |
| 底色 | 近白 + 网格 | 近白，无网格 |
| 角色描边 | 同色系深色 | 粗黑 |
| 角色画幅 | 300×300，细节多 | 简化，适配小尺寸 |
| 整体风格 | 手绘扁平 | iOS 悬浮卡片 |
| 网格 | 大面积使用 | 未使用 |

**推论**：网格是网站特有的表达，不必强加到 App 内。App 的语言是
「白卡片 + 大圆角 + 柔和阴影」。

按此，此前把网格设为全应用背景的处理需要调整——应限制在网站的展示性页面，
App 内的工具页与列表页用白卡片范式更贴合。
