# 归档区

本目录存放**已雪藏但仍需保留**的代码与数据。

## 为什么归档区在仓库根目录

`archive/` 必须位于仓库根目录，**不能放在 `public/` 下**。

Vite 会把 `public/` 的内容原样拷贝到 `dist/`。若归档物放在 `public/archive/`，被雪藏的代码与个人数据仍会进入构建产物并随应用发布——这既浪费体积，也可能造成隐私泄露。放在根目录则天然被排除在构建之外。

## 与删除的区别

| 处置 | 适用场景 | 可恢复性 |
| --- | --- | --- |
| 归档 | 功能完整但暂停使用，未来可能恢复 | 文件仍在工作区，可直接取用 |
| 删除 | 确定无用，或已有等价替代 | 仅可通过 git 历史找回 |

**注意**：归档前需确认目标文件已被 git 跟踪。未跟踪的文件一旦删除即永久丢失，因此**未跟踪文件只能归档，不能删除**。

## 目录约定

```
archive/
└── <模块名>/
    ├── ARCHIVE_NOTE.md     # 必需：雪藏原因、日期、恢复步骤、路径对照
    ├── legacy/             # 原实现
    ├── integration/        # 与之相关的外壳或桥接代码
    └── rewrite-wip/        # 未完成的改造骨架
```

每个归档模块必须有 `ARCHIVE_NOTE.md`，缺少说明的归档等同于垃圾。

## 维护约定

- 归档内容不参与构建、不参与类型检查、不参与 lint
- 归档物**不应**被 `.gitignore` 忽略——归档的意义就是可追溯
- 恢复时按 `ARCHIVE_NOTE.md` 中的路径对照表原路归位，并同步恢复相关引用
